Progressive Hydration Coverage ? What is "Progressive Hydration"? "Hydration" means filling in an item's details step-by-step:

1. Static Data is baked directly into the addon files.
2. Client DBC fills in weapon/armor types instantly from local game files.
3. Tooltip Scanning fills in green bonus stats from the server as you browse.

How to read these progress bars: In World of Warcraft, some item properties are always known locally by your game client (100% bars), while others are pre-baked into the addon's static catalog (72%–77% bars) so searches work even before your character has seen the item on the server. Any remaining items are filled in automatically at runtime the moment the server sends their tooltip.

Bi-Directional Source & Domain Tag Indexing (dungeon, boss-drop, zone-drop) ? Bi-Directional Source Indexing (100%) Every single item in the catalog knows exactly which dungeon, boss encounter, or zone trash table drops it—and every boss knows all of its items. 1,602 / 1,602 (100.0%)
Synchronous Client DBC Classification (C_Item.GetItemInfoInstant Slot & Subtype) ? Synchronous Client DBC Classification (100%) WoW's local game files (DBC) always know an item's icon, equipment slot (e.g. Two-Hand, Trinket, Head), and weapon/armor type (e.g. Sword, Mail, Cloth) for 100% of items without needing the server! 1,602 / 1,602 (100.0% In-Client)
Pre-Hydrated Static English Item Names (name) ? Pre-Hydrated Static Names (77.6%) 1,243 of the 1,602 items have their exact English name saved directly inside Items_Catalog.lua. For the remaining 359 custom WoW Forever items, the addon requests the name from the server automatically when opened. 1,243 / 1,602 (77.6%)
Pre-Hydrated Static Quality Tiers (q) ? Pre-Hydrated Quality Tiers (75.9%) q stores the item's rarity color (2 = Uncommon Green, 3 = Rare Blue, 4 = Epic Purple) so item links and borders render in the right color immediately on a cold cache. 1,216 / 1,602 (75.9%)
Pre-Hydrated Static Slot & Subtype Tags (slot, subType) ? Pre-Hydrated Slot & Subtype Tags (72.0%) 72% of items have their slot and subtype pre-baked in the static file, and the remaining 28% are filled in instantaneously at runtime by C_Item.GetItemInfoInstant (reaching 100% in-game!). 1,154 / 1,602 (72.0%)

Multi-Tag & Level Query Examples ? How Advanced Search Queries Work When Advanced Searching is enabled in Settings, you can combine equipment slots, weapon/armor types, primary stats, spell power, and level ranges in a single search.

Search Bar Input ? Search Bar Input What you type into the top-right search box in the Adventure Journal window (commas or spaces both work!). Normalized Query AST ? What is a "Normalized Query AST"? "AST" stands for Abstract Syntax Tree—it just means how the search engine breaks your words down into clean, standardized filter rules (tags + minimum/maximum level). Evaluation Behavior ? Evaluation Behavior How the engine filters the dungeon grid, boss list, and right-hand item page to show only matching items.
one handed, sword tag: one-hand tag: sword Intersects the one-hand and sword inverted index buckets, filtering dungeons, bosses, and encounter item lists to 1H swords.
cloth, chest, intellect tag: cloth tag: chest tag: intellect Matches cloth chestpieces and robes carrying +Intellect primary stat tags.
2h axe >=40 tag: two-hand tag: axe minLevel: 40 Parses space-separated shorthand tokens and enforces reqLevel >= 40 on all candidate two-handed axes.
sp, crit, lvl 30-45 tag: spell-power tag: crit level: 30–45 Expands aliases (sp → spell-power) and filters to caster gear usable between character levels 30 and 45.
